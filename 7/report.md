# Квантизация и hard-label дистилляция Qwen3 на MASSIVE ru-RU

Бейзлайн и ученик — Qwen3-8B, учитель — Qwen3-32B. Я использовал только train для калибровки и обучения, а качество измерял на всех 2033 примерах dev. Quality — среднее Intent Accuracy и Slot Micro F1.
## Условия экспериментов

Seed — 42. Для всех моделей одинаковы system prompt, список 60 intents и 55 типов slots, greedy decoding, enable_thinking=False, batch size=32 и максимум 128 новых токенов. Длинные промпты не обрезались. Целью дистилляции служили только сгенерированные ответы учителя.

## Квантизация

В AWQ/GPTQ использованы 4-битные веса, BF16-активации, симметричная квантизация и group size 128, кроме отдельного запуска с group size 64. SmoothQuant совмещён с GPTQ W8A8. В каждом запуске загружался исходный бейзлайн. Основная калибровка — 128 примеров; отдельно проверены 512. На MASSIVE использованы запросы в chat-формате, на WikiText — английские фрагменты в том же формате с сопоставимой длиной. Для 128 примеров суммарные длины составили 64858 и 64858 токенов соответственно.

При одинаковых настройках GPTQ разница Quality между калибровкой на MASSIVE и WikiText составила +0.0947 (MASSIVE минус WikiText). В обоих случаях использовалась одна инструкция; английские фрагменты WikiText подбирались по числу токенов к русским запросам. Поэтому сравниваются корпуса, различающиеся и языком, и содержанием.

Увеличение калибровки со 128 до 512 примеров изменило Quality на -0.1689, уменьшение group size со 128 до 64 — на -0.1307. У SmoothQuant переход от smoothing_strength=0.5 к 0.8 дал -0.0298. Самое большое изменение среди этих пар дала настройка «число калибровочных примеров».

Лучший квантизированный вариант — awq_massive: Quality 0.3915, изменение относительно бейзлайна +0.1015. AWQ и GPTQ использовали W4A16 с симметричной групповой квантизацией. SmoothQuant применялся вместе с GPTQ W8A8 (INT8-веса по каналам, динамические INT8-активации по токенам). Во всех конфигурациях lm_head оставлен в BF16. При оценке веса распаковывались в BF16. 

У AWQ рост Quality сопровождался увеличением Valid JSON Rate с 52.58% до 77.23%. Например, на запрос «какой сегодня день» (dev ID 127) бейзлайн выдал два JSON подряд со слотом timeofday=«сегодня», а AWQ — один правильный ответ со слотом date=«сегодня».

## Дистилляция

Учитель сгенерировал 4096 ответов на фиксированной подвыборке train. Сохранены все ответы; для обучения отбирались только ответы с допустимой JSON-схемой и EOS. После фильтрации осталось 3989 примеров. Из них использовались вложенные подвыборки.

Я обучал все параметры ученика в BF16 с AdamW, gradient checkpointing, batch size 4 и накоплением градиента за 4 шага (эффективный batch 16). Learning rate уменьшался по cosine schedule с warmup 5%. Loss считался только по токенам ответа учителя, включая EOS; промпт и padding маскировались значением −100. Каждый эксперимент начинался с исходного Qwen3-8B.

Quality бейзлайна — 0.2900, учителя — 0.5611, лучшего ученика — 0.5830. Ученик сохраняет 103.90% качества учителя и отличается от бейзлайна на +0.2930. Цель достигнута. Ученик превосходит бейзлайн. Разница Quality учителя и бейзлайна составляет +0.2711.

Лучшая конфигурация: 3989 ответов учителя, learning rate=2e-05, число эпох — 2. Я сравнил learning rate при одинаковых 1024 примерах, объём обучающих данных при одинаковом learning rate и число эпох на большей выборке. Изменения Quality составили +0.0388, -0.0025 и +0.0149 соответственно. Каждый запуск начинался с исходного бейзлайна. Результаты всех запусков приведены в таблице выше. 

При переходе от 1024 к 3989 ответам за одну эпоху Intent Accuracy изменился с 0.7629 до 0.7693, а Slot Micro F1 — с 0.3782 до 0.3668.
